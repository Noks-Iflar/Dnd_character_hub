# Dnd Hub — приложение для листов персонажей Foundry (кампания «Хвор»)

Веб-приложение для моей D&D-кампании «Хвор». Игроки смотрят и правят листы персонажей между сессиями, когда сервер Foundry выключен. Проект некоммерческий, для меня (мастер) и моих друзей (игроки).

Полный план с фазами: https://claude.ai/artifact/Nv34H3zHGrGYdpuyLyBGZz

## Цикл работы (главное правило)

Лист в каждый момент живёт в одном месте:

1. **После сессии** мастер запускает в Foundry макрос «Отправить партию». В приложение уходит снимок каждого персонажа.
2. **Между сессиями** игроки смотрят лист и правят разрешённые поля. Каждая правка пишется в журнал `changes`, снимок не меняется.
3. **Перед сессией** мастер запускает макрос «Забрать изменения», смотрит список и применяет правки к актёрам в Foundry.
4. **Во время игры** правка в приложении заблокирована (статус персонажа `in_game`) до следующего снимка.

На ранних фазах вместо макросов, которые сами ходят в Supabase, используются файлы: экспорт → загрузка в приложение → скачивание файла правок.

## Окружение Foundry

- Foundry VTT **14.370**, система **dnd5e 6.1.0**. Без перепроверки макросов эти версии не обновляем.
- Компендиумы на русском через модуль перевода, поэтому библиотеки выгружаем макросом изнутри Foundry, а не из файлов на диске.
- Сервер на компьютере мастера, сессии примерно раз в месяц.
- Хоумбрю-полей и модулей со своими ресурсами нет: только стандартные поля dnd5e.
- Портреты и иконки лежат на сервере Foundry и при выключенном сервере недоступны. Портрет макрос кладёт в снимок отдельно.
- Игроки живут не в России, мастер — в России. Если Supabase у мастера не открывается, используем VPN, план Б — PocketBase на VPS.

## Стек

- React + TypeScript (strict) + Vite
- PWA через `vite-plugin-pwa`: установка на телефон и офлайн-просмотр последнего листа
- Supabase (бесплатный тариф): Postgres, Auth (почта + пароль), Storage
- Хостинг на GitHub Pages: в Vite нужен `base: '/<repo>/'`, роутинг через `HashRouter`
- Деплой и keepalive через GitHub Actions
- DOMPurify для показа HTML-описаний

## Структура репозитория

```
src/                 приложение
  lib/snapshot/      разбор снимка, типы, применение правок к снимку
  lib/enrichers/     очистка описаний Foundry
  features/          экраны: sheet, gm-dashboard, library, lore, planner
foundry/             макросы Foundry (.js), каждый — отдельный файл
supabase/migrations/ SQL: таблицы и политики RLS
fixtures/            реальные экспорты персонажей и компендиумов (в .gitignore)
.github/workflows/   deploy.yml, keepalive.yml
```

Репозиторий публичный: GitHub Pages бесплатно работает только с публичными репозиториями. Поэтому:

- `fixtures/`, выгрузки компендиумов и любые `.env` всегда в `.gitignore`. Контент платных модулей в репозиторий не попадает.
- В код приложения можно класть только URL Supabase и anon key (через `VITE_` переменные). Ключ `service_role` никогда не попадает ни в код, ни в макросы.
- Безопасность держится на RLS, а не на скрытом коде.

## Данные

| Таблица | Что хранит |
| --- | --- |
| `profiles` | пользователь, роль `gm` / `player`, часовой пояс |
| `characters` | персонаж, владелец, `foundry_actor_id`, статус `in_game` / `between_sessions` |
| `snapshots` | снимки из Foundry, неизменяемые; старые не удаляются (история версий) |
| `changes` | журнал правок: персонаж, путь поля или id предмета, было, стало, автор, время, `applied_at` |
| `library` | записи компендиумов: тип, название, данные |
| `lore_pages` | страницы дневника и лора, флаг «только мастеру» |
| `availability` | свободное время игроков для планировщика (хранить в UTC) |

RLS: игрок читает и правит только своего персонажа, мастер видит всё. Страницы лора с флагом «только мастеру» игрокам не видны.

### Формат снимка

```json
{
  "schemaVersion": 1,
  "meta":     { "foundryVersion": "14.370", "systemVersion": "6.1.0", "actorId": "...", "exportedAt": "ISO-дата" },
  "source":   { "...": "actor.toObject() — то же, что Export Data" },
  "computed": { "...": "посчитанные значения: КД, ХП, модификаторы, спасброски, навыки, пассивки, инициатива, скорость, бонус мастерства, СЛ и атака заклинаний, ячейки, попадание и урон атак" },
  "portrait": "data URL или путь в Storage"
}
```

- `source` никогда не меняется в приложении. Лист = `source` + применённые к нему правки из `changes`.
- Значения в `computed` после правки могут устареть (например, КД после смены брони). Помечай их значком «может быть неточно», Foundry пересчитает при применении.
- Если `meta` показывает другие версии Foundry или dnd5e, приложение предупреждает мастера.

### Редактируемые поля

Только эти, остальное только для чтения:

- текущие и временные ХП, кости хитов, спасброски от смерти, истощение, вдохновение
- ячейки заклинаний, заряды умений и предметов
- монеты, количество предметов, надето или нет
- личные заметки
- добавление предмета из библиотеки (фаза 7)

## Оформление

Тёмное фэнтези в духе масляных артов кампании. Макет: https://claude.ai/artifact/F2ZSDA5DJqDN4yJfRqHYPk

- Цвета только через переменные из `src/index.css`, без захардкоженных hex в компонентах.
- Основа — тёмно-серый (`--accent`). Кроваво-красный (`--blood`) — хиты, крит, правки, ждущие мастера. Фиолетовый (`--magic`) — магия: ячейки, заряды. Голубой (`--tech`) — предтечи и служебное: статусы, ссылки, «может быть неточно».
- Шрифты: Cormorant Garamond (заголовки, числа), Cormorant SC (подписи разделов), Alegreya Sans (текст). Подключены локально через `@fontsource`, чтобы работать офлайн.
- Кнопки и поля не меньше 44 px по высоте.

## Правила кода

- TypeScript strict, без `any` на границах данных. Типы снимка лежат в `src/lib/snapshot/`.
- Вёрстка сначала под телефон.
- HTML из Foundry показывать только через DOMPurify. Энричеры чистить: `@UUID[...]{Имя}` → «Имя», `[[/r 1d6]]` → «1d6».
- Все даты в базе в UTC, показывать в часовом поясе пользователя.
- Логику разбора снимка и применения правок покрывать тестами (Vitest) на файлах из `fixtures/`.
